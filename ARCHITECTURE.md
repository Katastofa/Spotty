## 2. Что в архитектуре ОТСУТСТВУЕТ

Ни одного из перечисленного нет в текущей архитектуре и нет в коде:

второй MCU · Raspberry Pi · ROS · Teensy · Arduino Nano · FEETECH serial bus ·
IMU · OLED · PS2-приёмник · ультразвуковые датчики · PIR · RGB-светодиоды ·
аудио/MP3 · телеметрия батареи · датчики тока · концевики · энкодеры ·
обратная связь по положению · симуляция · хост-ПО · аварийный останов (E-STOP)

Добавление любого из них — отдельное архитектурное решение, которое должно быть
задокументировано здесь до реализации.

### Решение 2026-09-26: IMU добавлен как ИЗМЕРИТЕЛЬ

Оператор: IMU физически подключён, SCL GPIO15, SDA GPIO16, INT GPIO18.
Из списка выше IMU этим решением **снят**.

- Шина: отдельная, `Wire1` (второй контроллер I2C ESP32-S3), не шина PCA9685.
- Код: `code/spotty_imu.h`, подключён в `gait_test`. Тип чипа определяется
  при старте (MPU-6050/6500/9250, BNO055; ICM-20948 только опознаётся).
- Роль: только телеметрия — крен, тангаж, курс, сводка за прогон `w`.
  В траекторию не входит. Единственное действие — аварийный стоп по
  наклону, **выключен** по умолчанию (`imu stop <град>`).
- INT подключён, но не используется: опрос по таймеру раз в 6 мс.
- Ориентация модуля в корпусе НЕ ПРОВЕРЕНА: `SPOTTY_IMU_AX_*` в
  `spotty_config.h`, процедура — `imu mon`.
- Обратная связь по IMU в походку — отдельное будущее решение.

## 3. Программная архитектура

Текущая: одна прошивка на одном MCU, без ОС, без задач/RTOS-абстракций
в существующем коде, блокирующее исполнение движений.

```
setup()                      инициализация, БЕЗ подачи команд на серво
  |
loop()
  |
  +-- чтение последовательного порта
  +-- разбор команды
  +-- вызов функции движения   <-- блокирующая, на основе delay()
        |
        +-- расчёт угла
        +-- угол -> импульс (калибровочные массивы)
        +-- запись в PCA9685
```

**Известное архитектурное ограничение:** модель движения блокирующая
(`delay()`), поэтому во время выполнения движения приём команд невозможен и
аварийный останов программно недоступен. Это ограничение унаследовано от
исторического кода и должно быть учтено при переносе на ESP32-S3.

## 4. Известные пробелы переноса на ESP32-S3

Зафиксированы как факты о коде. **Это не задание на исправление** — прошивка на
этом этапе не меняется.

| Пробел | Где | Почему важно на ESP32-S3 |
|---|---|---|
| `Wire.begin()` без указания пинов | `code/nova_sm3/nova_sm3.ino` не вызывает `Wire.begin(SDA, SCL)` | на ESP32-S3 пины I2C назначаются программно; значения по умолчанию зависят от варианта платы |
| Адрес PCA9685 не задан явно | `Adafruit_PWMServoDriver pwm = Adafruit_PWMServoDriver();` | используется адрес по умолчанию библиотеки; фактический адрес платы UNKNOWN |
| `Serial.begin(9600)` | там же | на ESP32-S3 канал может быть USB-CDC, а не UART; поведение и скорость отличаются |
| Ширина `int` | весь код | на AVR 16 бит, на ESP32-S3 32 бита; арифметика углов/импульсов должна быть перепроверена |
| Частота ШИМ 50 Гц | `setPWMFreq(50)` | значение унаследовано; пригодность для QY3240MG HV не проверена |
| Отсутствие E-STOP | архитектурно | на ESP32-S3 это по-прежнему отсутствует |

## 5. Целевая архитектура

Целевая архитектура **совпадает** с текущей физической архитектурой:
один ESP32-S3 → I2C → PCA9685 → 12 × QY3240MG на платформе SpotMicro (KDY0523).

Цель этапа — не изменить архитектуру, а сделать её работоспособной:
установить отображение каналов, направления, калибровку и безопасные пределы.
