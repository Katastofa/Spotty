# Обучение своими руками и проверка на железе

Пошагово: от запуска поиска на своей машине до сверки того, что робот
реально сделал, с тем, что обещала модель. Общее описание симулятора —
в `README.md`, здесь только рабочий порядок.

---

## 0. Что нужно один раз

```
pip install pybullet numpy
```

`bin\trace.exe` уже лежит рядом — это **настоящая прошивка**, собранная под
Windows. Копии походки в Python нет и не будет: и обучение, и просмотр, и
сверка считают траекторию тем же кодом, который залит в ESP32.

Проверка, что всё на месте:

```
python run_once.py height=150
```

Должно напечатать «продольная база 186 мм — ИЗМЕРЕНО (M4, рулетка)» и итог
прогона. Если ругается — дальше идти незачем.

## 1. Посмотреть глазами

```
python view.py --params results\best_robust_m100.json
```

Восемь ползунков, каждый подписан буквой команды на роботе. Крутите —
походка пересчитывается настоящей прошивкой и тут же проигрывается.

Два ползунка, на которые стоит смотреть особо:

* **`body shift 0=off (B)`** — перенос корпуса по фазе. На нуле поведение
  такое же, как было до 12.09.
* **`joint rate limit deg/s (m)`** — предохранитель прошивки. Если в строке
  состояния загорелось **`CLIPPED`**, ограничитель режет команду, и робот
  идёт **не той походкой**, которую посчитал генератор. Это не авария, это
  повод менять параметры.

## 2. Обучение

```
python learn_robust.py
```

Что происходит: метод перекрёстной энтропии перебирает шесть чисел походки,
и **каждый кандидат гоняется по шести мирам** с разными ПРИНЯТЫМИ массами,
ЦТ и распределением веса по звеньям. Балл сводится как *среднее минус
половина разброса* — набор, блестящий при одной удачной массе и падающий при
другой, проигрывает набору, одинаково приличному везде.

Это и есть ответ на «весов пока нет»: мы не угадываем массу, мы ищем
походку, которой она не важна.

| ключ | по умолчанию | зачем менять |
|---|---|---|
| `--gens` | 10 | больше поколений — дольше и чуть лучше |
| `--lam` | 16 | кандидатов в поколении |
| `--cycles` | 6 | длина прогона; короче — быстрее, но вердикт мягче |
| `--workers` | 2 | по числу ядер |
| `--maxrate` | 100 | предел скорости сустава, с которым ищем |
| `--seed` | 1 | другой seed — другой поиск; одинаковый seed даёт одинаковый результат |
| `--gui` | выкл | показывать окно: видно, как шагает каждый кандидат |
| `--realtime` | выкл | с `--gui`: в реальном времени, а не бегом |

Время: примерно `gens × lam × 6 × 1.5 с / workers`. При умолчаниях и
двух ядрах — около десяти минут; с `--gui` вдвое дольше, потому что
параллельность выключается.

### Прогресс в консоли

Строка на поколение, и в ней всё, что нужно:

```
пок  4/10 [########            ] лучший  -0.886 | миров 5/6 | элита  -1.302 |
          height=134 lift=15 shiftgain=1 span=31 swing=974 vel=61 |
          прошло 1:40, осталось ~4:30
```

* **миров 5/6** — главное число. Это НЕ балл, это в скольких мирах лучший
  кандидат поколения устоял. Цель — чтобы стало 6/6.
* **лучший / элита** — балл лучшего и средний по элите. Баллы отрицательные,
  пока хоть один мир падает: падение штрафуется на 5, и эти пять ничем не
  перекрыть. Растущий (то есть менее отрицательный) балл при неизменном
  «миров» означает, что кандидат учится падать позже и идти дальше.
* **height, lift, span…** — центр облака поиска, то есть куда он сходится.
* **осталось** — по фактическому времени прошлых поколений.

### Окно: включить и выключить

```
python learn_robust.py --gui              смотреть, как ищет
python learn_robust.py --gui --realtime   то же, но в реальном времени
python learn_robust.py                    без окна (по умолчанию, быстрее)
```

Что происходит с окном:

* показывается **только номинальный мир**, остальные пять считаются без
  картинки — смотреть можно в одно окно, а рисование стоит времени;
* в окне подпись `gen 4/10  cand 7/16` и параметры текущего кандидата, так
  что видно, на что смотришь;
* **поиск идёт в один процесс.** Окно, открытое дочерним процессом, не
  закрывается по Ctrl+C, а на Windows открывалось бы заново на каждый
  процесс. Поэтому при `--gui` параллельность отключается, и скрипт об этом
  прямо говорит. Плата — примерно вдвое дольше на двух ядрах;
* **закрыть окно = прервать поиск.** Результаты предыдущих поколений
  останутся в `results\learn_robust_*.json`.

Смотреть на поиск целиком обычно незачем: он часами не идёт, а полезнее
посмотреть на результат. Окно ценно в двух случаях — когда непонятно, ПОЧЕМУ
всё падает, и когда хочется убедиться, что физика не сошла с ума.

### Посмотреть результат отдельно

Это не требует `--gui` при обучении и работает в любой момент:

```
python view.py --params results\best_robust_m100.json
```


В конце поиск сам проверяет победителя на **расширенной** сетке из 13 миров,
куда добавлены трение, жёсткость контура, латентность и слабое серво — числа,
по которым он не обучался. Набор, хороший только на своей сетке, здесь и
сыплется.

Результат: `results\best_robust_m100.json` и лог поиска
`results\learn_robust_m100.json`.

### Если хочется поменять, что считается хорошей походкой

Веса лежат в `spotty_sim\evaluate.py`, класс `Weights`, каждый подписан:
путь, снос, курс, качка, проскальзывание, работа приводов, отставание
сустава, падение. Менять их — это и есть «сказать оптимизатору, какая
походка считается хорошей». После правки просто запустить поиск заново.

## 3. Полётная карта

```
python export_set.py results\best_robust_m100.json
```

Делает два файла:

* **`ПОЛЁТНАЯ_КАРТА_<тег>.md`** — что это за набор, чем проверен, что обязана
  напечатать предполётная, что делать, если пойдёт не так;
* **`set_<тег>.txt`** — голые команды по одной в строке, вставить в терминал
  целиком.

Числа в карте считает прошивка, а не пересказывает Python.

## 4. Прогон на роботе

**Только на подвесе, питание с ограничением тока, по `SAFETY.md`.**

1. Залить `gait_test`, открыть терминал на 115200.
2. Вставить содержимое `set_<тег>.txt`. Последняя строка — `p`.
3. Прочитать, что напечатала предполётная. Должно быть
   `Предполётная проверка пройдена (пределы).`, требуемый пик скорости —
   тот же, что в карте, и ни одного `[!!]`.
4. `n` — выход в позу. **Это движение.**
5. `w 6` — пойти. `x` останавливает в любой момент.
6. **Сохранить весь вывод терминала в файл.**

## 5. Сверка: сделал ли робот то, что обещала модель

```
python compare_real.py log.txt --params results\best_robust_m100.json
```

Робот во время `w` печатает пять раз в секунду углы, которые **реально ушли
в серво** — после клампа по пределу и после ограничителя скорости. Стенд
кладёт в CSV ровно те же величины. Значит их можно сравнить число в число,
привязавшись к фазе, которую робот печатает сам.

Сверка берёт установившийся цикл (первый после выхода из позы — переходный,
он отбрасывается), интерполирует эталон по фазе и считает по каждому суставу
СКО, максимум и **смещение** — среднюю разницу со знаком.

Допуск считается, а не назначается: робот печатает фазу с двумя знаками
(±0.005 цикла), плюс мёртвая зона серво 0.54°. Всё, что больше их суммы,
округлением не объясняется.

**Что проверяет:** что прошивка в роботе посчитала то же, что модель — те же
нули и пределы, ту же геометрию, те же параметры. То есть что вы ввели
именно то, что собирались, и что во флеше не лежит забытая накладка.

**Чего НЕ проверяет:** дошло ли серво туда, куда ему велели. Обратной связи
по положению в проекте нет — робот печатает команду, а не факт.

### Как читать расхождение

| что видно | почти наверняка |
|---|---|
| смещение одного знака у ОДНОГО сустава | его нуль: накладка во флеше или правка мимо `spotty_config.h` |
| смещение у всех суставов одной ноги | карта каналов или геометрия этой ноги |
| большое СКО при нулевом смещении | параметры походки другие: период, размах, duty |
| расходится только на пике | ограничитель скорости режет — сверьте `m` и требуемый пик |

Построчную выгрузку для разбора в таблице даёт `--csv разбор.csv`.

## 6. Порядок на один вечер

| | что | время |
|---|---|---|
| 1 | `python learn_robust.py` | ~10 мин |
| 2 | `python view.py --params results\best_robust_*.json` — посмотреть | 5 мин |
| 3 | `python export_set.py results\best_robust_*.json` | секунда |
| 4 | прогон на подвесе по карте, сохранить лог | 15 мин |
| 5 | `python compare_real.py log.txt --params ...` | секунда |

Если пункт 5 сказал «СОВПАЛО» — модель и робот думают одинаково, и дальше
имеет смысл говорить о том, как он ходит. Если нет — сначала разобраться,
потому что любые выводы о походке до этого момента будут про разные машины.
