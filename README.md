# OpenQuadruped (рабочее имя каталога: Spotty)

> **О репозитории.** Здесь код, симуляция и документация. Модели рам (STL/STEP/Blender) и видео
> в git не входят: это сторонние проекты со своими лицензиями и большие файлы — ссылки на
> источники в `FRAMES_RESEARCH.md` и `frames_stl/ГИБРИД_журнал.md`. Пароли Wi-Fi в
> `code/gait_test/spotty_wifi.h` заменены заглушкой `changeme123` — задать свои перед прошивкой.

Четвероногий робот на платформе **OpenQuadruped**, управляемый одним **ESP32-S3**
через **PCA9685** и 12 сервоприводов **QY3240MG HV**.

> **THIS IS THE CURRENT PROJECT ARCHITECTURE.**
>
> ```
> ESP32-S3  →  I2C  →  PCA9685  →  12 × QY3240MG HV
> Mechanical platform: OpenQuadruped
> MCU count: 1
> Servo power: отдельная батарея 2S LiPo 50C
> ```
>
> **Historical firmware must not be treated as the current hardware specification.**

**Цель проекта:** привести существующую архитектуру прошивки в рабочее состояние
именно на этом железе.

**Статус:** робот собран и ходит стабильно; поломки механики устранены. Подробности — в PROJECT_STATUS.md.

### ЗАИМСТВОВАННЫЙ КОД И ЛИЦЕНЗИИ

| Файл | Источник | Лицензия |
|---|---|---|
| `code/gait_test/oq_gait.h` | [OpenQuadruped](https://github.com/adham-elarabawy/OpenQuadruped), Adham Elarabawy | MIT, © 2020. Копирайт сохранён в шапке файла |

Портированы **только алгоритмы**, из пяти файлов: `control_library/bezier.py`
(контрольный многоугольник переноса, вычисление кривой, поворот траектории),
`control_library/gait_planner.py` (фазовая машина), `gait_parameters.py`
(`T_stance = 2·L_span/v_d`), `body_ik.py` (поза корпуса),
`depracated/RPi/main_interface.py:40` (контрольные точки опоры).

**Что из того же проекта НЕ взято, и это принципиально:**

- **их IK ноги** (`leg_ik.py`, `InverseKinematics.cpp`) — делится на ноль
  ровно на нашей геометрии. Формула предполагает вынос оси бедра от оси хипа
  с двумя ненулевыми составляющими (у них 11.369 и 63.763 мм); по нашим STL
  общий перпендикуляр 10.75 мм идёт чисто по Z, вторая составляющая нулевая,
  и `r0 = h1·sin(a4)/sin(a3)` обращается в деление на ноль. Проверено
  численно. Используется своя `legIK` в `gait_test.ino`;
- **`Util::angleConversion`** — костыль под их посадку серво
  (`weird_offset = 50`, `angle + 135`, ветвление по номеру ноги). У нас
  `JOINT_ZERO_US` / `JOINT_SIGN` / `JOINT_MIN_US` / `JOINT_MAX_US`;
- **все их числа.** Бедро/голень у них 109.868 / 144.580 мм, отношение 1.316;
  по нашим STL 108.31 / 116.51, отношение 1.0757. Другая машина. Политика
  проекта: чужие числа не переносятся, переносится только форма формул.
  Единственное исключение — безразмерные коэффициенты формы кривой безье
  (80.5 / 100 / 138.9 / 178.6 / 103.2 / 82.6), которые масштабируются на
  наши размеры и потому переносимы по построению.

Умолчания параметров тоже НЕ взяты у автора: его пресеты (перенос 200…400 мс)
требуют 305…375 °/с по колену на нашем железе при разрешённых 100. Подобраны
заново, см. комментарий у `pSwingMs` в `gait_test.ino`.

## Историческая архитектура — НЕ ТЕКУЩАЯ

В репозитории присутствуют документы, описывающие три другие архитектуры.
Ни одна из них не является текущей:

1. **ROS Kinetic + Raspberry Pi + PCA9685** (`docs/1.md`–`4.md`, окт. 2025)
2. **ROS Noetic + Raspberry Pi + FEETECH STS3020 + IMU + FSR** (`README_OLD.md`, март 2026)
3. **NovaSM3: два MCU (Teensy 4.0 + Arduino Nano) + датчики + PS2** (внешний проект)

Названия NovaSM3, SpotMicro, KDY0523, ROS, Raspberry Pi, Teensy, Arduino Nano,
FEETECH STS3020 **не указывают** на текущую архитектуру.

## Правила работы с репозиторием

1. Исторические файлы не удаляются, не изменяются, не переименовываются и не
   перемещаются без явного разрешения оператора.
2. Значения из исторического кода — кандидаты, а не измерения.
3. Неизвестные параметры остаются помеченными как UNKNOWN.
4. Физические факты не выводятся из исходного кода.
5. До подачи питания — прочитать SAFETY.md.
